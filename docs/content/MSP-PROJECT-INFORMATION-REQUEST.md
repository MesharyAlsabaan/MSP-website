# MSP Project Information Request

Date: 2026-10-15 · For: MSP management · Purpose: verified facts for project pages, case studies and service pages

The website will publish only what this document confirms. Nothing will be inferred or invented. For each project, the table shows what the site says **today** (from the live CMS). Please correct it, and answer the questions, in the empty column. Write "unknown" or "do not publish" rather than guessing. Where a field must not be public (a private owner, a confidential client), write "confidential": the page will simply omit it.

**How answers are used.** Answers go into the CMS (admin → Projects) by an authorised editor. Case-study text can be structured with `## ` headings in the description: Overview, Design challenge, Our approach, Architectural experience, Engineering considerations, MSP scope, Outcome. The page shows only the sections that have content.

**Rules for outcomes.** For projects that are not completed and occupied, describe design intent ("the design aims to…"). "Verified outcomes" means something MSP can evidence: completion, handover, an authority approval, occupancy, a client statement in writing, or measured data. Do not include estimates.
